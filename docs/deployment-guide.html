Prerequisites — have these ready

10 minutes. If everything is ready, jump to Phase 1.

  • GitHub account — the same ImXforever that hosts the AGI and Xbot repos.
  • Railway account — go to railway.app → Login with GitHub. The 30-day trial gives $5 credit; upgrade to Hobby ($5/mo) to continue (card required).
  • cPanel + DNS access for zenovix.ae — you have it.
  • Telegram — we will create a new bot.
  • OpenAI or OpenRouter key — platform.openai.com/api-keys (min $5) or openrouter.ai/keys. Without it the bot answers from the knowledge base; with it, fully smart.
  • The zenovix-chat package (v3.2) — unzip it; railway-variables-READY.env is needed in Phase 3.
🎯 The 4-move plan: ① AGI code to GitHub → ② Railway deploys it + Postgres/Redis + variables → ③ domain zenovix-production.up.railway.app + Telegram webhook → ④ widget v3.2 on the site pointing at Railway. Then: admin panel, TWA, admin bot — all already alive.
1

GitHub — get the code (with the CORS patch) into the repo

15 minutes · one file changed: app/main.py (adds CORS so the site widget can call the API).

1-1Open the AGI repo

Go to github.com/ImXforever/AGI and make sure the project is complete (app/ folder, Dockerfile, railway.json…). A private repo is fine — Railway gets access to it.

1-2Replace app/main.py with the patched version

In the repo: open the app folder → click main.py → the ✏️ pencil icon.

Add this block right after the line app.add_middleware(RequestContextMiddleware) (if you copy the whole file from this package, it is already in place):

# Website widget on zenovix.ae calls the public API cross-origin.
import os as _os
from fastapi.middleware.cors import CORSMiddleware

_allowed = [
    o.strip() for o in _os.getenv(
        "ALLOWED_ORIGINS", "https://zenovix.ae,https://www.zenovix.ae"
    ).split(",") if o.strip()
]
if _allowed:
    app.add_middleware(
        CORSMiddleware,
        allow_origins=_allowed,
        allow_methods=["GET", "POST", "OPTIONS"],
        allow_headers=["Content-Type"],
        max_age=86400,
    )

Commit changes at the bottom. (The pro way: clone locally, drop the patched file in, push — same result.)

💡 This patch is the only code difference from the original repo. If you skip it, the widget on zenovix.ae gets CORS errors in the browser console and live chat fails — so this step matters!
2

Railway — create the project and first deploy

20 minutes · Railway understands the repo's own Dockerfile.

2-1New project from the GitHub repo

In railway.app → New Project → Deploy from GitHub repo → pick AGI. Empty list? Account Settings → Applications → grant Railway access to the AGI repo.

2-2Let the first build run

Railway detects the Dockerfile and builds (3–5 minutes). The first deploy will likely go red — totally normal! We have no database or variables yet; Phase 3 fixes that.

2-3Add PostgreSQL and Redis

On the project canvas → + New → Database → Add PostgreSQL. Then + New → Database → Add Redis.

Two small services appear next to AGI. Keep their names Postgres and Redis — the env file references them by those names.

2-4File storage: Bucket (Railway's built-in S3)

+ New → Storage → Bucket (or from Marketplace). Keep its default name — the env file wires it via ${{…}} references.

⚠️ If the 4 R2 variables stay empty/red after saving: open the Bucket service → Credentials tab → copy the 4 values (ENDPOINT / ACCESS_KEY_ID / SECRET_ACCESS_KEY / BUCKET) into the AGI variables by hand.

Variables — the heart of the setup

20 minutes · railway-variables-READY.env in the package has everything prepared.

3-1Prepare four values first

WhatWhere from
Bot tokenTelegram → @BotFather → /newbot → name: Zenovix · username: zenovix_bot → copy the 123456:ABC-… token
Your numeric idTelegram → @userinfobot → /start → the numeric Id (e.g. 123456789)
Strong admin passwordMake one (16+ chars) — used to log into /admin
LLM keyOpenAI: sk-… or OpenRouter: sk-or-…

3-2Paste into the Raw Editor

Open the AGI service → Variables tab → Raw Editor → paste the full content of railway-variables-READY.env (after filling it in) → Save.

Make sure these 6 are filled:

TELEGRAM_BOT_TOKEN=PASTE_YOUR_BOT_TOKEN
TELEGRAM_ADMIN_IDS=PASTE_YOUR_TELEGRAM_NUMERIC_ID
TELEGRAM_WEBHOOK_SECRET=PASTE_16PLUS_CHAR_RANDOM_SECRET
ADMIN_BOOTSTRAP_PASSWORD=PASTE_STRONG_ADMIN_PASSWORD
WEB_SECRET=PASTE_16PLUS_CHAR_RANDOM_SECRET
DIRECT_API_KEY=PASTE_YOUR_OPENAI_KEY
  • Twilio/SendGrid not needed yet: the file ships with WHATSAPP_ENABLED=false and EMAIL_ENABLED=false — those are later channels; enable whenever ready.
  • DATABASE_URL=${{Postgres.DATABASE_URL}} and REDIS_URL=${{Redis.REDIS_URL}} — do not touch; Railway injects the plugin values.
⚠️ After saving, a new deploy starts automatically. Still red? Open Deployments → latest → View Logs and read the message (usually one missing variable — Phase 9 troubleshooting).

3-3First green test 🎉

AGI service → Settings → Networking → Generate Domain → you get something like agi-production-xxxx.up.railway.app. Open in a browser:

https://YOUR-RAILWAY-URL/healthz
✅ Seeing {"status":"ok",…}? The brain is alive in the cloud!

5

Telegram + admin panel + TWA — every admin surface

20 minutes · this is where "connecting the panel to the admin bot" happens — because both live inside this same AGI.

5-1Connect the bot webhook

Open this URL in a browser — fill the three … placeholders with your values (bot token, domain, the same secret from the env file):

https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://zenovix-production.up.railway.app/tg/webhook&secret_token=<WEBHOOK_SECRET>
✅ Seeing {"ok":true}? The customer bot is connected. Now send /start to your bot in Telegram — the platform's main menu should appear!

5-2Test the admin bot

Since TELEGRAM_ADMIN_IDS = your id, send /admin to the same bot — the full list of admin commands (settings, orders, tickets…) answers back. This bot + this id = the admin channel.

5-3The admin web panel

Go to https://zenovix-production.up.railway.app/admin → log in with ADMIN_USERNAME (default: zenovix-admin) and ADMIN_BOOTSTRAP_PASSWORD. Inside: dashboard, orders/quotes (the HITL queue), tickets, customers, catalog, reports…

🔒 Security: after your first login, create a real user for yourself in the panel, then remove/rename the bootstrap account.

5-4TWA — the admin panel inside Telegram

In BotFather: /setmenubutton → pick your bot → URL: https://zenovix-production.up.railway.app/admin/twa.html. The bot's menu button now opens the admin web app inside Telegram.

5-5Run the golden loop ✨

Submit a test quote from the bot (or the widget after Phase 6). You should see, simultaneously:

  1. Your Telegram receives a "New website lead ZX-…" alert,
  2. the customer gets the ZX reference,
  3. the lead appears in the panel and can be acted on from all three places (admin bot / TWA / web panel).

<script src="/js/zenovix-chat.js?v=3.2" defer></script>

6-3The Flask fork: keep it, but parked (optional)

If you already installed the fork backend on cPanel (the beginner guide), leave it — its role is now fallback: if Railway ever goes down, temporarily point the two embed URLs at /chat/api/… on your host and light KB chat stays up. Never installed it? Not required at all.

8

Monitoring, backup, updates

  • Monitoring: uptimerobot.com (free) → new Monitor → https://zenovix-production.up.railway.app/health every 5 min → email alerts. Railway also restarts the container if it crashes.
  • Database backup: Railway → Postgres service → Backups tab (plan-dependent) + a monthly manual pg_dump kept somewhere safe.
  • Updating the brain: any change on GitHub (even from the web, one commit) → Railway deploys automatically. No commands needed.
  • Updating the widget: upload the new js file and bump ?v= in the embed (e.g. v=3.3) so browser caches refresh.
  • Cost: glance at Railway → Usage weekly; the Hobby plan is enough to start.

Troubleshooting — the rescue table

SymptomCause and fix
Deploy red, log says ConfigError: required variable …That variable is missing from the Raw Editor (usually a leftover PASTE_ or a plugin not added yet). Add the exact name from the log → auto-deploy.
Log: LLM_MODE=mock is not permittedMake sure APP_ENV=production comes with LLM_MODE=direct and a real key — mock is intentionally locked in production.
/healthz unreachable / 502Deployments → View Logs. Build green and logs clean? Check Settings → Networking; verify DNS at dnschecker.org (CNAME propagation).
Widget opens but chat says "Network problem" / console: CORS1) Is the Phase 1-2 patch really in the repo? 2) Is ALLOWED_ORIGINS exactly https://zenovix.ae,https://www.zenovix.ae (no trailing slashes)? 3) Was a new deploy created after the change?
setWebhook replies ok:falseWrong token/secret or a URL without https. Rebuild it with the exact env values.
Bot silent but healthz greenSet the webhook again (needed after any domain change) and keep secret_token equal to TELEGRAM_WEBHOOK_SECRET.
Cannot log into /adminADMIN_USERNAME/ADMIN_BOOTSTRAP_PASSWORD come from env — every variables change requires a fresh deploy. Cookies: open via https.
The 🔊 button does not appearSome browsers (notably older iOS) lack Web Speech — the button only renders where supported. Chrome/Edge/desktop Safari are fine. For server-side neural voices: future phase /api/public/speak with edge-tts (blueprint §10).
Microphone missingChrome/Edge only (SpeechRecognition). Firefox is unsupported — the button is hidden on purpose, not a bug.
429 in chatRate limit (default 30/min — RATE_LIMIT_PER_MINUTE in the env). Wait a few minutes.
Can I do Railway without a card?
The 30-day trial ($5 credit, GitHub-verified account) starts without a card; continuing on Hobby ($5/mo, plus plugins in practice) needs one. If you only want to "see it" for now, you can do Phase 6 with the Flask fork on cPanel and add Railway later — the widget does not change, just two URLs.
Adding WhatsApp/email later?
All adapters are inside AGI. In the env file set WHATSAPP_ENABLED=true and EMAIL_ENABLED=true and fill the 6 Twilio/SendGrid/IMAP values in that section → commit/restart. A full guide lives in the repo: DEPLOY-EGL-FA.md (Persian).
Can I start cPanel-only first?
Allowed: setup-guide.html documents the cPanel-only path (Flask fork). But the admin panel / admin bot / TWA do not exist in that path — Railway is required for those. Whenever you are ready, you only swap the widget's two URLs and you are on the cloud brain.
