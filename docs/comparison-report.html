Comparison: original AGI platform vs the zenovix-chat v3.2 fork

Based on the actual code of both repositories — not guesswork; with verbatim evidence from the files ✔

📅 Sep 10, 2026 🔬 Method: direct code comparison + a 45/45 test suite ⚖️ Verdict: the fork = the platform's web channel, carved out

📦 Original — /AGI

the full "Zenovix" enterprise bot platform — version 1.6.0
  • 457 files / ~17MB — FastAPI + Docker + CI
  • bot brain: 94 modules in app/core (~22k lines) — orchestrator, RAG, memory, skills, LLM
  • admin panel: 30 API modules + full UI (RBAC, audit, CRM…)
  • 5+1 channels: Telegram, WhatsApp, email, Instagram, Twitter + web
  • infrastructure: PostgreSQL + Redis + R2 + parquet archive
vs

💬 Fork — zenovix-chat v3.2

an embeddable chat widget + a single-file backend
  • 26 files / ~160KB — single-file Flask, no heavy dependencies
  • widget ~2,040 lines: the whole bot environment (menu/shop/HITL) in the browser
  • backend ~640 lines: the same /api/public/* contract
  • web channel only — designed for ordinary cPanel hosting
  • storage: JSONL on the host + the customer's localStorage
🎯 One-liner for stakeholders: the fork is not a "mini copy" of the platform; it is the platform's web channel — API contract, bot copy, reference formats and validation rules were lifted verbatim from the original code, while the heavy chat brain stays on the main server.

What exists only in the fork

  • 🎨 The full WhatsApp skin: ticks/double-ticks, typing, doodle wallpaper, presence, unread badges, sounds, emoji, reactions — AGI doesn't have these (its Telegram/WhatsApp output is those apps' own UI).
  • 🔵 SIM mode: the whole experience works with zero backend — great for demos and development.
  • ➕ In-chat e-mail capture (v3.1) and voice layer + /track (v3.2, Xbot port).
  • 🧩 2-line install on any site + a JS API (ZenovixChatAPI).
  • ✅ A 45-test suite (jsdom + real HTTP) that keeps verifying parity on every change.

✅ Verdict: for the stated goal ("a site widget with the original bot's capabilities, deployable on cPanel"), the fork is delivery-ready: the contract, copy and references are real and identical to the platform, covered by the 45/45 suite. For the real admin panel/bot, deploy AGI itself on Railway (see the architecture blueprint).
⚠️ Be transparent with stakeholders: 1) manager approval inside the widget demonstrates the flow; it is not wired to AGI's admin panel; 2) fork leads are stored in a jsonl file, not PostgreSQL; 3) free-form answers depend on the KB / LLM key you configure. All three disappear with the Railway deployment.
